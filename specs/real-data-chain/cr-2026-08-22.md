## Blockers

1. **Mootdx exceptions escape the FetchResult boundary**
   - Location: `src/uq/adapters/mootdx_source.py`.
   - Network/client failures can bubble up instead of returning typed upstream errors.
   - Fix: catch instrument-level and client-level failures separately; return `UPSTREAM_ERROR` with retry metadata.

2. **TDX history is silently limited to one 800-bar request**
   - Location: `src/uq/adapters/mootdx_source.py`.
   - Requested dates outside the latest window can become empty without proof.
   - Fix: paginate by date/count and emit explicit partial/error when requested coverage cannot be proven.

3. **Complete routing trusts declared capability rather than observed result**
   - Locations: `src/uq/routing/router.py`, `src/uq/pipeline/daily.py`.
   - A primary result marked `EMPTY` is currently usable even though expected-row policy is absent.
   - Fix: recompute route coverage from status, delivered fields, row keys, and expected-row evidence.

4. **Calendar, universe lifecycle, suspension, and expected-key coverage are absent**
   - Location: `src/uq/pipeline/daily.py`.
   - Non-trading days, unlisted securities, delisted securities, and provider omissions cannot be distinguished.
   - Fix: require trading-calendar membership plus explicit no-row policy before publication.

5. **Cross-validation is optional in practice**
   - Location: `src/uq/quality/gate.py`.
   - Default minimum coverage is zero and missing secondary sources are skipped silently.
   - Fix: encode required validation, minimum overlap, and lineage status `not_performed|partial|passed`.

6. **Schema validation is not strict**
   - Location: `src/uq/contracts/schema.py`.
   - Extra columns and weak date checks may enter canonical output.
   - Fix: enforce exact schema columns and normalized day-resolution date types.

7. **Installed CLI cannot resolve repository config**
   - Locations: `src/uq/cli.py`, `pyproject.toml`.
   - Config paths depend on source-tree layout; source adapters are not declared as extras.
   - Fix: add explicit project/config arguments, clean-install test, and optional dependency groups.

8. **Run reports are not persisted**
   - Location: `src/uq/cli.py`.
   - Stdout-only diagnostics do not satisfy audit/replay requirements.
   - Fix: persist run ID, request, statuses, quality checksum, versions, warnings, errors, and timing outside canonical data.

9. **Exception paths break CLI exit-code contract**
   - Locations: `src/uq/pipeline/daily.py`, `src/uq/cli.py`.
   - Routing, client construction, storage I/O, and manifest failures can produce tracebacks.
   - Fix: convert known failure families into `IngestReport`; map them to stable exit codes.

10. **Specification still contains stale Tushare-first runtime assumptions**
    - Location: `specs/real-data-chain/spec.md`.
    - Current executable path is TDX-first, while some acceptance/runtime text remains Tushare-oriented.
    - Fix: separate historical Tushare R1 from active TDX-first hybrid R1-H.

## Major Gaps

- Partial-field and partial-row semantics differ across demo, Tushare, and TDX adapters.
- Tushare authentication/dependency failures are raised before becoming `FetchResult`.
- Provider error classification relies too heavily on message text.
- Tushare batch requests have no safe batch size or retry policy.
- Adapter schema versions are inconsistent and not router-validated.
- `FetchResult` lacks run/request IDs and raw-response provenance.
- Quality checksum does not cover input fingerprints, key, required fields, and thresholds.
- Storage I/O failures are not converted into structured publication failures.
- Manifest parsing accepts malformed JSON/types with native exceptions.
- One public TDX server is hard-coded; there is no failover.
- Health probes are not integrated with ingest or persisted diagnostics.
- Retry/backoff/circuit-breaking is unimplemented despite `retryable` metadata.
- Structured logging, latency, attempt counts, and server health are absent.
- README overstates current PIT guarantees relative to the implemented daily-bars chain.

## Minor Issues

- Rename or supplement `FetchResult.is_usable` with an explicit publishability decision.
- Load cross-validation minimum coverage from dataset contracts.
- Tighten accepted string/date dtype aliases.
- Remove or use unused compatibility-dtype definitions.
- Add run/config/code fingerprints to `IngestReport`.
- Replace fragile exception-path local-variable checks.
- Ignore/remove `.DS_Store`.
- Mark `run_daily_ingest()` as planned or replace documentation examples with `DailyIngestPipeline.run()`.
- Label milestones as `implemented`, `partially_implemented`, or `not_started`.

## Long-Term Readiness Order

1. Source reliability: typed failures, pagination, failover, retry, health integration.
2. Coverage correctness: calendar, lifecycle, suspension/no-row policy, expected keys.
3. Typed failure boundary: adapter-to-report-to-stable exit code.
4. Independent validation: required overlap, lineage status, golden samples.
5. Deployment reproducibility: clean install, extras, config resolution.
6. Auditability: persistent run reports, request/response provenance, fingerprints.

Until these close, outputs are suitable only for exploratory research and must
not back factor libraries, automated backtests, or production workflows.

## Second Careful Review (2026-08-22)

Verdict: still **exploratory research prototype**. The first remediation pass
closed some failure-boundary issues but did not close the core correctness gaps.
Thirty-six passing tests cover too much forward-path behavior.

### New Blockers

1. **Route completeness uses calendar dates**
   - Location: `src/uq/routing/router.py`.
   - Weekends and holidays are incorrectly treated as expected sessions.
   - Fix: inject a trading-calendar provider; without one, use `unverified`, never `complete`.

2. **Pipeline does not consume route completeness**
   - Location: `src/uq/pipeline/daily.py`.
   - A primary `SUCCESS` result can bypass coverage status.
   - Fix: require explicit route completion or an explicit no-row/partial policy before publication.

3. **Mootdx datetime-index normalization can fail by column layout**
   - Location: `src/uq/adapters/mootdx_source.py`.
   - The indexed branch can look up price columns on the wrong frame after dropping/reordering.
   - Fix: normalize by named columns after a single deterministic index reset; add a reordered real-shaped fixture.

4. **TDX history remains limited to one 800-bar request**
   - Location: `src/uq/adapters/mootdx_source.py`.
   - Older requests may become silently empty or partial.
   - Fix: paginate and prove requested-range coverage; otherwise emit typed partial/upstream error.

5. **Publication I/O is not a structured storage boundary**
   - Location: `src/uq/pipeline/daily.py`.
   - Disk/permission failures are classified indirectly through the outer handler.
   - Fix: wrap publication I/O in a dedicated report boundary with stable exit semantics.

6. **Run-report writing is not atomic or tested**
   - Locations: `src/uq/cli.py`, `src/uq/pipeline/daily.py`.
   - Report I/O can traceback, and IDs lack request/config/code provenance.
   - Fix: atomic report writer, fingerprints, request metadata, and CLI integration tests.

### Remaining Major Findings

- Additive schemas do not constrain allowed extra columns.
- Date validation lacks empty-frame/NaT/Parquet-roundtrip golden behavior.
- Cross-validation is still silently skipped when a secondary source is absent.
- Router accepts mismatched adapter/schema envelope versions.
- Tushare batching and provider-error classification remain unsafe.
- Configuration and quality rejection share exit code 3.
- `uv.lock` does not yet include the new `real` extras.
- Documentation still describes partial fixes as completed.
