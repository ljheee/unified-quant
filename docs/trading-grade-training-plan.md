# 交易级训练落地计划

> 更新于 2026-11-06；代码基线 `e6d9e8b4c21d156edac47d3c12d153bd9320d003`，本文和进度文档为该基线上的工作树修订。当前证据与实际完成情况见[交易级训练进度](trading-grade-progress.md)；重写前的完整规划及历次修订见[历史快照](trading-grade-training-plan-history.md)。

## 1. 目标与完成标准

建立可追溯、可复现、适用于 A 股交易约束的训练、模型比较、组合回测与模拟盘流程。比较必须建立在可证明的时间可得数据、预先冻结的模型选择协议和一致的交易假设上，并能解释收益、风险、成本和容量。诊断跑通、通过自动测试、覆盖一年、取得正收益分别是不同的结论，不能互相替代。

计划完成需要同时满足：

1. 数据来源、证券生命周期、交易日历、行情、执行事实、公司行为、因子及其时点可得性有可核查的契约和质量证据；不具备的数据被明确标记，不能由占位值冒充真实事实。
2. 训练、验证、模型选择和样本外评价时间隔离；模型与对照使用相同的交易日、标的资格、基准、费用和约束。历史已观察结果作为探索结果，不再宣称是独立确认集。
3. 在一致的账户、成本和公司行为语义下完成连续样本外模型比较；报告涵盖收益、风险、成本、换手、容量、基准、压力情景和可对账归因。至少一年的覆盖只是必要条件，市场状态覆盖、历史数据完整性和独立评审须分别证明。
4. 完成计划内模型选择、因子、组合、模拟盘及可复现归档的功能缺口，分别通过边界和端到端验证；不可取得的数据项如实保留状态，不以伪造数据填平缺口。
5. 进入模拟盘策略评审须达到预先设定的扣佣金、税、滑点和冲击后的正期望、稳定基准超额及风险上限，并通过可执行性和可复现性检查。模拟盘工程验证可以在测试口径下先行，不能因此宣称已满足策略评审。
6. 新模型替换线性基线须在至少一年独立 OOS 上同时达到更好的扣成本超额收益和信息比率，收益不能集中于单一行业、风格或少数标的，复杂度增加须有可解释的收益；未达标则保留基线或不通过结论。
7. 正式质量结论或发布须使用适用的独立审批与信任锚，完成对应认证门槛；结果未达到门槛时保留失败证据，不以改口径代替结论。

## 2. 已确认的边界

- 采用现有 TDX、Tushare 2000 接入与可核查的交易所/发行人资料，先检查可用范围和时间精度。CSI-All 成分采用已接受的月度近似，不能将其描述为逐日精确历史成分。
- 分析师预期数据当前不具备，属于可选增强，**不是基线比较的前置条件**。其他基本面、交易行为和暴露数据按可用性与时点证据逐项接入。
- 测试密钥可用于隔离诊断、自动测试和验证工作流；测试密钥及机械质量报告不构成独立质量批准。正式质量结论再使用适用的独立签名和评审。
- 模型比较包括线性基线与 LightGBM；先冻结选择规则和预算，再对未观察过的样本外窗口作独立评价。当前已观察的 264 个 OOS 交易日只能作为探索和工程诊断。
- 公司行为遵循已批准的 v4 口径：除权除息日确认税后现金及股票应收并纳入净值，现金在支付日可用，股票在上市日入账并遵守 T+1；配股标的按已批准的全窗口排除策略处理。全窗口排除本身可能使用未来信息，须单独披露其时点局限并评估影响，不能将它表述为已验证的 PIT 策略。
- 本计划的执行目标是模拟盘，不包括接入真实券商或实盘交易。既有 schema 纯追加扩展、已批准的 trust-anchor 更新及归档 telemetry 纳入 checksum 按既有裁决执行。
- 不单独重跑全量流程只为做性能基准；在下一次确有研究价值的训练或研究链执行中顺带记录性能和资源。

## 3. 起点与关键约束

隔离测试根中，线性与 LightGBM 均已完成两个各 132 交易日的独立折，并生成逐折配对报告；合计 264 个 OOS 交易日、397 个日历日。该运行没有证明历史 PIT 完整性、市场状态覆盖或质量授权。逐折账户重置，不能直接等同于一个连续账户。[进度文档](trading-grade-progress.md)记录具体结果、制品和限定条件。

现有 v3 连续回放要求完整窗口采用一致的 v3 公司行为面板；v3 引擎对全窗口有公司行为的目标标的执行拒绝检查。使用现有诊断面板做交集预检，线性模型第一折有 106 个决策日、71 个标的，LightGBM 第一折有 115 个决策日、101 个标的与该全窗口集合相交；第二折均为零。这是预检而非已执行的连续回放。全窗口事先排除公司行为也存在未来信息风险，不能靠改写已发布权重或放宽守卫掩盖。

诊断执行事实含 `is_st=False`、`industry=None` 等简化假设，部分缺失前收由 `1.0` 填充，部分状态和涨跌停由规则推断；公司行为面板仅覆盖已接入的除权除息事件，配股完整性未证明。回测中受影响的实际成交及其收益影响尚未量化。行情 readiness 通过只证明其声明范围内的行情与生命周期检查通过，不能推导出执行事实、公司行为或所有输入的历史 PIT 完整。

## 5. 修订后的落地顺序

### M0：冻结现状并隔离诊断结论

- 固化现有制品、代码版本、参数、数据根、签名用途和已观察 OOS；列出占位字段、时点假设、公司行为交集及潜在前视风险。保留已发布制品的不可变性。
- 审计既有训练数据、标签、模型选择和逐折目标的来源及时间边界，确定是否可以在修正事实后复用；不能证明时重建。早期 11 决策日基线曾记录代码指纹和环境锁摘要为零、标签上市日期映射未受 checksum 保护；须核查其现状和可复现边界，不能将后续新制品自动视为修复了旧制品。
- **验收**：形成可复查的假设和血缘清单；诊断、独立确认和正式质量结论边界明确。此阶段不要求生产签名。

### M1：补数据事实与数据契约

- 并行核查 TDX、Tushare 2000 及权威公告的覆盖与原始记录；按日历对齐核验上市、退市、停复牌、ST、涨跌停、行业、市值及公司行为的历史可得性和时间精度，区分未知与真实值。
- 为 v4 应收、支付、上市、配股及复权等字段补充来源、版本、缺失策略和一致性检查；不能获得时保持明确的阻断或降级状态。
- 对更长历史做小范围源能力和样本探测，确认覆盖与权限后再拉取和治理。因子公式、合成测试、版本化契约等不依赖真实数据的开发可与数据收集并行。
- **验收**：每个用于目标比较的字段具备可追溯来源、as-of/精度说明和通过的质量检查；未满足者不能冒充已验证事实。分析师预期缺失不阻断基线。

### M2：补连续账户与模拟盘的 v4 能力

- 在不改变既有 v3 制品语义的前提下，设计并版本化 v4 连续共享账户回放、跨折持仓及资金、应收/结算状态、终止清仓和模拟盘对账。遵循已批准公司行为规则，明确配股排除的 PIT 限制。
- 增加独立折多折汇总制品：绑定每折的协议、输入和结果、账户重置/再投资假设，可独立读回重算；与连续账户回放报告采用不同的结论和资本语义。
- 覆盖现金和股票支付时点、T+1、跨折事件、停牌/涨跌停、无法清仓、费用、会计恒等式、幂等及兼容性等回归测试；无法清仓必须明确报告，不能假定成交。
- **验收**：有版本化契约、失败关闭边界、可重复测试与文档；v3 既有数据仍按原语义读取。实现完成本身不证明真实数据质量。

### M3：重建有效输入并运行必要的配对实验

- 根据 M0 审计结果复用合格的分数/权重，或以新请求重新训练和生成；保持两个模型的标的资格、执行、资本、成本和风险协议一致。旧 OOS 保持探索属性。
- 构建完整窗口治理日历、原始价格、执行事实及公司行为面板，并覆盖目标执行日与期末清仓所需的额外交易日；绑定数据和配置后分别运行两模型的连续账户与逐折对照。
- 同步运行相同交易约束下可构建的全 A 等权、市值加权及行业中性基准，并采集 Qlib 导出复用、报告核验、总耗时及峰值资源指标；保留失败或缺数的证据。
- **验收**：完整血缘与读回校验、两模型输入可比、账户从头到尾对账；不能满足前置条件时报告阻断原因，不以逐折累计冒充连续收益。

### M4：完成评价、归因、风险和模拟盘验证

- 发布可重算的年度/窗口配对比较，区分逐折汇总与连续账户：绝对及年化超额收益、IR、IC/RankIC、持仓日与全区间胜率、最大回撤与恢复时间、换手、成本、交易失败、行业/市值/流动性暴露、分年度/市场状态、基准和样本覆盖。五日重叠标签的 IC 显著性使用逐日截面序列并至少设 HAC lag=4。报告逐折结果及差异，避免只展示汇总。
- 实现并核对逐证券、行业、市值/风格和费用归因；将股息、股票应收及结算引起的净值变化纳入会计对账。历史行业/市值不可用时标明该维度未验证。
- 以可追溯成本和流动性假设执行容量及压力情景、风险约束和模拟盘回放/对账，校验基准的成分、执行和成本一致性。确定性 paper 回放用于验证流程、状态与约束，并比较回测成交差异，不能证明真实成交率或市场冲击。
- **验收**：指标可由绑定制品重算，收益归因与 NAV 对账，风险及模拟盘结果完整披露限制；一年覆盖、PIT、市场状态和质量授权逐项单独判定。

### M5：补模型、因子、组合及更长数据窗口

- 将验证集 LightGBM 选择结果和试验预算纳入受治理研究链、签名选择凭证和模型制品；隔离训练、验证及确认集，记录所有候选和失败。已看过的 OOS 不得被重新称为未触碰确认集。
- 完成计划中的基本面、行为因子契约、测试与数据 onboarding；基本面按公告而非报告期对齐，盘后数据决策使用至少滞后一 session。验证行业、市值和流动性中性化，逐因子评价增量、IC 稳定性、共线性及换手成本，再进行跨期 OOS 验收。基于真实历史行业和市值等输入验证组合构建、风险约束和基准。无可用或可证明时点的数据时，保留未完成状态及获取条件。
- 经探测后补齐更长可用历史、成熟标签和数据质量；末尾 28 个部分有标签的交易日不足以构成新的独立一年确认窗口。
- **验收**：实现、治理链、可重现制品和相应测试齐备；每个真实数据驱动功能有可追溯样本及覆盖说明，不把合成测试当作真实覆盖。

### M6：独立确认及正式资格

- 预先冻结新窗口、标签、模型候选、选择预算、交易与成本方案及失败处理；在未观察的新 OOS 上比较，并独立证明覆盖、时点质量以及上涨、下跌、震荡市场状态。形成标签审计结论，核验 eligibility 的时点可知性和标签与 T+1 可执行路径的偏差；当前 close-to-close 标签不能直接声称完全可交易。
- 进行适用的独立质量评审、生产信任锚/签名及完整认证矩阵；保留所有失败和不利结果。是否具备质量资格由实际证据决定，不以任何模型必须盈利为预设。
- **验收**：完成范围内所有可交付功能与测试，独立结果和授权可复核；无法取得的数据、时间窗口或授权单独列为未完成，不静默关闭。

## 6. 验证与维护

每个实现变更按受影响子系统维护契约和文档，包含针对失败边界的回归与必要的端到端测试。质量证据记录精确代码版本、数据生成、签名用途、命令和结果；Qlib 行为变更使用 Qlib 环境验证。依赖、锁文件或发布资格变化按项目规范重跑适用认证矩阵。真实服务验证仅在实际调用并可追溯时声明成功。

当前状态、已执行的真实运行与下一项工作以[进度文档](trading-grade-progress.md)为准；详细旧决策和原始轮次保存在[规划历史](trading-grade-training-plan-history.md)及[进度历史](trading-grade-progress-history.md)。
